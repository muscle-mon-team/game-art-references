# FRAME — 게임 아트 레퍼런스

Muscle Mon의 비주얼 방향을 탐색하기 위한 공개 게임 아트 레퍼런스 라이브러리입니다. 실제 게임의 스크린샷을 모아 색감, 질감, 캐릭터 비례, 배경 구성과 전투 시인성을 비교합니다.

**[웹 갤러리 열기](https://muscle-mon-team.github.io/game-art-references/)**

현재 카탈로그는 `data/catalog.json`에 있습니다. 게임과 이미지 수는 웹에서 해당 파일을 기준으로 계산합니다.

## 이 저장소의 목적과 범위

- 귀여운 동화풍, 장난감, 클레이, 공예풍을 중심으로 여러 비주얼 방향을 비교합니다. 손그림, 픽셀아트, 어두운 화면과 런앤건도 비교 자료로 포함합니다.
- 특정 디자인을 미리 확정하지 않고, 좋아하는 장면을 모으면서 원하는 방향을 구체화합니다. 현재 Muscle Mon 캐릭터나 배경을 유지한다는 전제를 두지 않습니다.
- 선정한 장면의 근거를 스타일 규칙과 구현 인수인계로 연결합니다. 실제 게임 수정은 승인된 대상 게임 저장소에서 그 저장소의 지침을 따라 진행합니다.
- PC, 콘솔, 모바일 모두 수집 대상입니다. Steam과 Nintendo 자료에서 시작해 쿠키런과 모바일 공식 자료를 보강하고 있습니다. 선별 모음이므로 모든 게임을 망라하지 않으며, 목록에 없다고 제외 대상으로 정한 것은 아닙니다.
- 게임 소스나 실행 파일을 개발하는 저장소는 아닙니다. 실제 게임 프로젝트인 `Muscle-Mon_Godot`과 분리되어 있습니다.
- 스크린샷은 감상과 비교를 위한 자료입니다. 이 저장소가 게임 제작에 사용할 모델, 텍스처나 재사용 라이선스를 제공하지는 않습니다.

## 둘러보기

- 게임별 카드 또는 여러 게임의 스크린샷을 섞어서 보기
- 2D, 2.5D, 3D 및 스타일 태그로 필터링
- 한국어와 영어 게임명, 분위기, 질감 검색
- 측면 시점만 보기와 장면 수 기준 정렬
- 원본 이미지 확대, 게임 안의 스크린샷 이동, 공식 출처 열기
- 브라우저에 저장되는 즐겨찾기와 장면별 메모
- 최대 네 장을 나란히 비교
- 내 선택 JSON 내보내기와 다른 브라우저에서 가져오기

즐겨찾기와 메모는 서버나 GitHub에 전송하지 않습니다. 현재 브라우저의 로컬 저장소에만 보관됩니다. 다른 기기에서 보려면 JSON 파일을 내보내고 가져와야 합니다. 가져오기는 기존 선택에 합치는 방식입니다.

## 분류 기준

이 분류는 게임 아트 감상을 위한 편집 기준이며, 엔진이나 이동축에 관한 기술 명세가 아닙니다.

- **2D:** 그림, 손그림, 픽셀 등을 중심으로 읽히는 화면
- **2.5D:** 주로 측면에서 보는 입체 또는 혼합 표현
- **3D:** 입체 공간을 주로 사용하는 게임. 고정 시점과 자유 시점 모두 포함

혼합형과 깊이 이동이 있는 게임은 게임 설명에 표시합니다. 스타일 태그는 비교를 위한 관찰 기준이며 제작사의 공식 기술 분류가 아닙니다.

## 다른 LLM에게 게임 적용을 맡기려면

1. [적용 안내](docs/REFERENCE_TO_GAME.md)에 따라 원본을 열어 관찰하고, 게임 및 이미지 ID와 출처를 기록합니다.
2. [스타일 정리 양식](docs/templates/STYLE_BRIEF.md)으로 관찰한 사실과 제안, 미확인 사항을 나눕니다.
3. 사용자가 선택한 규칙과 실제 수정 권한을 [구현 인수인계](docs/templates/IMPLEMENTATION_HANDOFF.md)에 기록합니다.
4. 대상 게임의 최신 지침과 구조를 확인한 뒤 작은 화면부터 적용하고 검증합니다.

즐겨찾기는 관심 표시이며 디자인 확정이 아닙니다. [작성 예시](docs/examples/TOY_STAGE_PROPOSAL.md) 역시 아직 승인되거나 구현된 디자인이 아닙니다.

## 이미지와 권리

스크린샷 원본은 저장소에 업로드하지 않습니다. Steam, Nintendo와 모바일 공식 스토어, 제작사 및 퍼블리셔의 공개 페이지와 프레스킷에서 확인한 이미지 URL에 연결합니다. 각 이미지에는 원문 페이지 링크가 있습니다.

실제 플레이 화면과 공식 스토어의 소개 이미지를 구분합니다. 홍보 문구와 합성 요소가 있는 자료는 게임 설명과 원본 데이터의 검수 기록에 그 사실을 표시하며, 합성 장면을 실제 플레이 카메라와 HUD의 근거로 사용하지 않습니다.

이미지와 게임의 권리는 각 제작사와 권리자에게 있습니다. 이 라이브러리는 이미지를 게임 제작용 에셋으로 제공하거나 재사용 라이선스를 부여하지 않습니다.

출처의 URL 변경, 이미지 삭제, 네트워크 또는 제공사의 연결 정책으로 일부 이미지가 표시되지 않을 수 있습니다. 이 경우 각 카드의 공식 출처 링크를 이용하세요.

## 로컬 실행

별도 패키지 설치나 빌드 없이 Python 3만 있으면 됩니다.

```sh
python3 -m http.server 8000
```

브라우저에서 http://localhost:8000 을 엽니다. HTML 파일을 직접 더블클릭하는 대신 HTTP 서버로 실행해야 카탈로그를 읽을 수 있습니다.

## 자료 갱신

추가 경로, 입력 형식, 실행 순서는 [기여 지침서](CONTRIBUTING.md)에 있습니다. 먼저 원본 데이터를 수정한 뒤 카탈로그를 생성합니다. `data/catalog.json`만 직접 수정하면 다음 생성 때 변경이 사라집니다.

| 파일 | 역할 |
| --- | --- |
| `data/steam-seeds.tsv` | 수집할 Steam 앱 ID와 사람이 정한 분류, 태그, 관찰 포인트 |
| `data/steam-catalog.json` | Steam 수집기가 생성한 이미지 URL과 출처 데이터 |
| `data/console-sources.json` | Nintendo, 쿠키런과 모바일 공식 페이지에서 확인해 수동으로 정리한 자료. 같은 형식으로 다른 제작사의 자료도 추가 가능 |
| `data/catalog.json` | 두 자료를 합쳐 웹에서 읽는 생성 파일 |
| `data/collection-errors.json` | 마지막 Steam 수집에서 실패한 항목 |
| `data/verification.json` | 마지막 전체 이미지 HTTP 검증 결과. 실행 시점의 기록이며 실시간 상태는 아님 |
| `index.html`, `styles.css`, `app.js` | 갤러리의 구조, 스타일, 검색과 표시 및 브라우저 내 선택 저장 |
| `scripts/` | 자료 수집, 카탈로그 생성, 데이터와 이미지 주소 검증 |

HTTP 이미지 응답 성공과 실제 플레이 화면 확인은 서로 다른 검증입니다. 검색 결과의 썸네일이나 정상 응답만 보고 메뉴, 컷신, 홍보 그림을 플레이 화면으로 기록하지 않습니다.

## 배포

GitHub Pages가 `main` 브랜치의 루트 폴더를 게시합니다. `.nojekyll` 파일로 Jekyll 처리를 생략하며, 정적 HTML/CSS/JavaScript와 JSON만 사용합니다. 서버, 데이터베이스, API 키는 필요하지 않습니다.

원격 반영과 공개는 작업 요청이나 유지보수 권한의 범위 안에서 진행합니다. 로컬 수정, GitHub 반영, Pages 빌드 완료, 실제 웹 표시 확인을 구분해서 기록합니다.
